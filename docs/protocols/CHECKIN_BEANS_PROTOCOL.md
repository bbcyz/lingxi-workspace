# 签到专属 AI 豆

## 使用与范围

入口为「签到有礼」中「自动任务」右侧的「签到专属 AI 豆」。本功能使用签到活动的专属 AI 豆余额，与「我的权益」中的 AI 豆分别查询。

签到情况、自动任务和 AI 豆共用同一个当前账号：电脑在左侧选择，手机在页面上方选择。右侧只展示该账号，不重复列出账号或提供账号搜索、签到状态筛选；AI 豆面板显示当前账号，面板内不另设账号选择器。顶部「立即签到」只针对当前账号；多账号操作使用「批量签到」或 AI 豆中的「执行全部账号」。自动任务配置和组团仍按全体有效共享账号统一执行。

截至 2026-11-25 晚间，当前官方列表中有 24 项任务已接入并实际验证，业务请求、签名和结果核对均由 Python 完成。移动及兼容服务可按原有协议登录；新增的百度地图、淘宝和菜鸟任务使用一次性授权并按账号加密保存的本人身份，合作方登录失效后需重新授权，尚未实现其独立账号的自动登录。运行时无需连接手机、ADB、浏览器自动化或合作 App。Windows / Python 服务通过 FFmpeg 实际解码播放任务视频；独立 Android 客户端使用自身的 MediaPlayer，后者尚未进行新版 APK 实测。

完整的当前任务结果、未接通步骤及本次账号范围见 [逐项任务表](CHECKIN_BEANS_TASKS.md)。下文带日期的旧核对记录保留为历史证据，身份授权和接通状态以本段及文末最新进展为准。

每日任务覆盖所有有效共享账号，从自动签到的配置时间开始检查，默认北京时间 08:00。晚启动、新增或恢复登录的账号核对官方状态后补做；已经领取的项目跳过。也可在面板中执行当前账号或全部有效账号。

只有官方确认可领取，才发送领豆请求；之后再次查询官方任务状态及余额。兑换话费券需在本地面板确认奖品、账号和所需 AI 豆，再核对库存、提交并查询结果。尚未真实兑换话费券，本次验证不包含券到账验收。

## 协议与凭据

- 主活动查询使用 `task/taskList`、`task/taskInfo`、`task/getExchangeList` 和库存查询。完成、领奖、兑换各自使用官方支持的接口，不混用任务令牌。
- 查询与普通浏览任务核对任务名称、类别、HTTPS 主机和路径，且只跟随已验证的官方跳转。真实查询或访问成功、满足官方时长后，才按公开签名算法调用 `task/finishTask`。
- 视频任务以 APP 网关 `sourceId=017027` 换票，登录 CMLIVE，解密并核对本账号手机号。使用该任务专属 `taskToken` 换取完成令牌，实际播放后调用 `advert/signIn/openFinish`，再由主活动核对并领豆。
- 云盘任务以 `sourceId=001304` 换票，通过 `user/login/ssoHW` 登录。公开前端协议的 DES、PKCS7、动态请求头和 MD5 签名在 Python 中实现。解密返回的手机号并核对账号，取得目标活动授权和跳转票据后访问实际活动页。等待时间取任务要求与活动 `browseTaskDuration` 的较大值；使用 `cloudDisk/getOneTaskInfo` 返回的 `ctoken` 调用 `cloudDisk/openFinish`，最后查询移动侧任务并领豆。
- 周三活动浏览使用 `https://wx.10086.cn/hlwyxhdhub/api/open/_pub/task/getOneTaskInfo`，请求体为 `{jtToken: taskToken}`；取得独立 `cToken` 后按官方时长浏览，再调用同一命名空间的 `openFinish`。前一轮对旧 7 日任务的诊断误用了主签到命名空间及父令牌，返回 HTTP 500；这是错误请求，不能作为官方正确接口故障的证据。新流程使用当前任务新取得的凭据，未重放旧错误请求。
- 咪咕视频使用主签到会话的 `user/getYDRZToken?targetSourceId=012012` 获取官方一次性票据，按 `migu_login_callback.htm` 的 `migutokenforencrypt` 流程登录。校验加密手机号与本账号一致，查询 `/gateway/user/videox/v1/user-info/`，访问实际业务页，再调用 `/gateway/ability/videox/task/openFinish`。公开 SDK 的 AES-ECB、PKCS7、MD5 `ensign` 和响应解密均由 Python 实现。
- 咪咕会话范围为 `checkin:migu-video`，按服务器 `expiredOn` 的毫秒时间保存并复用，沿用官方 `userInfo` Cookie；不因主 APP 凭据版本变化重复换票。主 APP 被要求重新登录时，仍有效的签到活动会话可继续用于查询和无人值守；签到活动自身到期后不拿旧 APP Cookie 反复重建。
- CMLIVE 与云盘凭据分别使用 `checkin:cmlive`、`checkin:cloudtrial` 范围，按账号加密保存并合并并发初始化。共享凭据版本变化不触发重登。未知有效期不套用其他活动时长；按官方明确失效响应恢复一次只读请求。提交失败或结果不确定时不自动重放。未决标记允许最多两次间隔五分钟的结果复核，先只读查询；仍未确认时不提交，已确认完成时才继续领奖。
- 视频实际播放失败、直播无内容、任务入口变化或官方要求额外授权时，保留具体原因，继续其他独立任务。官方任务列表临时为空时只展示当天最近核对记录，不据此发起领奖。
- 写入前持久化未决标记。任务完成与领奖按当天范围核对，兑换按当月范围核对；不把昨天的已领取状态当成今天已完成。

百度地图签名材料来自本次成功查询返回的 `token.key` 和 `ctime_str`，不写死、不伪造服务器材料。公开网页的字段排序、MD5 与编码规则在 Python 中实现，离线向量与公开 JavaScript 计算结果一致。只有服务端确认是导入账号，才访问实际任务页和发送回传。

淘宝 MTOP 的签名、参数序列化、令牌和 Cookie 同步均在 Python 中完成。只读请求遇到官方明确的 H5 令牌为空或过期响应时，使用服务端已签发的新令牌恢复一次；合作回调、领奖等写请求不自动重放。会话失效、需人工验证和普通业务拒绝分开处理，不强制续期共享 APP 身份。

淘宝和菜鸟复用同一有效兼容认证域，按官方 Cookie 到期信息缓存；短期 H5 签名令牌到期不等于重新登录账号。百度地图身份单独缓存。共享 APP 凭据版本变化、页面轮询和程序重启不会重新读取手机或建立合作方登录。缓存缺失时明确提示授权缺口，不使用其他账号的登录补位。

每条任务都先记录提交意图，再访问实际业务、提交对应合作方接口。接口接受不代表奖励到账；仍由主签到活动查询任务状态、领取 AI 豆并复查余额。明确拒绝与响应丢失分别处理：前者解除本次已知失败意图，后者保留待核对标记，先查询、不重放。
